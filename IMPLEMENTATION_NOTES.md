# Implementation notes — audit enhancements (2026-07-12)

What was implemented from AUDIT.md, in commit order, plus anything
deferred and why.

## Implemented

1. **Rho source-of-truth drift fixed.** `tools/build_bundle.py` emits
   `_meta.rho` from `teams_calibrated.json` as `constants.DC_RHO`
   (fallback -0.074 only when the meta is absent). `index.html` applies
   every bundle constant in `hydrateFromBundle()` via
   `applyConstants()`, and `tools/embed_calibrated.py` writes the fitted
   rho into the embedded calibrated-data block so the offline fallback
   matches. Test: bundle rho == calibrated meta rho.

2. **Season-odds Monte Carlo conditioned on played results.**
   `model.json` gains an additive `results` field (played 2026/27
   matches with scores, from the openfootball cache; empty pre-season).
   The web engine pins those scores (`f.fixed`) in `buildGrids()` and
   `buildScenarioGrids()` — manual Scenario Lab pins still override —
   and only simulates the remaining fixtures; the odds table states how
   many results the run is conditioned on. Pre-season behaviour is
   bit-for-bit identical (verified by test on the Python mirror).
   Python: `simulate.pin_results()`, `monte_carlo(results=...)` (both
   the standard and noise paths) and `plsim montecarlo --results FILE`
   (accepts a results list or a model.json bundle).

3. **Live accuracy ledger.** Each weekly run scores the previous run's
   `data/forecasts.json` against newly played fixtures (RPS + Brier via
   `plsim.backtest`) and appends per-run + cumulative aggregates to
   `data/ledger.json`; after the refit it writes fresh forecasts for the
   next two unplayed matchdays. The ledger ships in `model.json`
   (additive `ledger` field) and as an embedded fallback, and the
   Accuracy tab renders a "Live track record" section (rolling RPS vs
   the static backtest 0.2123 and market 0.1994 benchmarks) with a
   collecting state until entries exist. Both steps are best-effort so
   they can never break the refit.

4. **Projected final table** in the Season odds tab: clubs ranked by
   mean points with xPts, modal finishing position, title/top-4/
   relegation %, colour bands (champions / UCL top 5 / Europa+Conference
   6th–7th / relegation). Same MC aggregates, no extra compute.

5. **PWA basics.** `manifest.webmanifest` (name "PL Simulator",
   standalone, theme colour `#2a78d6`), 192/512 icons generated by the
   dependency-free `tools/make_icons.py` (pure zlib/struct PNG writer;
   Pillow was unavailable), full-bleed so the same files serve `any` and
   `maskable`. `sw.js` is network-first for the shell + `model.json`
   (cache fallback offline) and cache-first for icons/manifest.
   `index.html` registers the SW and carries theme-color/apple-mobile
   tags; `netlify.toml` serves `sw.js` with `no-cache`.

6. **CI** (`.github/workflows/ci.yml`): `python3 -m unittest discover
   tests` on push and pull_request.

7. **Input validation.** `plsim.teams.load_ratings` rejects non-object
   teams, non-numeric/non-positive attack/defence/elo/home (with
   messages naming team, key and file) and defaults a missing `home` to
   1.0. `hydrateFromBundle` validates the bundle (20 teams with positive
   numeric attack/defence; 38×10 fixtures of known team pairs) before
   swapping any state; invalid bundles are dropped with a
   `console.warn` and the embedded fallback stands.

8. **Automated odds refresh.** `tools/weekly_update.py` calls
   `tools/build_odds.py` per recent season inside try/except (missing
   package or mirror outage just logs a note). The recalibrate workflow
   installs the odds package best-effort.

9. **Dormant chart states.** The title-race chart shows "Collecting
   weekly snapshots — N of 3 needed" with the live count; the movers
   strip explains it fills in after the next recalibration.

10. **ARIA tabs + shareable URLs + OG tags.** Proper WAI-ARIA tablist
    (roles, aria-selected/-controls/-labelledby, roving tabindex,
    Left/Right/Home/End keys). Active tab and Scenario Lab pins are
    encoded in `location.hash` (`#tab=...&pins=...`, replaceState) and
    restored with validation on load. `og:image` + Twitter tags point
    at the 512px icon.

Also: `altair` and `pandas` added to requirements.txt; the
`teams_calibrated.json` `_meta` provenance is now explained by a
`_meta.note` field (written by `cal.write_ratings` going forward and
added to the committed file) plus a README sentence.

## Deferred / decisions

- **Per-match "why" explanation** (audit comparison table): out of the
  ten scoped items; the club drill-down already shows ratings, form and
  per-fixture probabilities.
- **Seed/scenario-run auto-execution from the URL**: the hash restores
  the tab and pins but does not auto-run the scenario simulation, to
  keep page load predictable (the Season-odds auto-run is unchanged).
  Seed is not encoded — it lives in Model settings and defaults to 42.
- **Forecast horizon** is the next two unplayed matchdays per weekly
  run (weekly cadence can cover a midweek round); easily widened via
  `FORECAST_MATCHDAYS` in `tools/weekly_update.py`.
- **Icons**: Pillow is not in the toolchain, so icons are flat-gradient
  "PL" marks from a pure-Python PNG writer rather than anti-aliased
  artwork. Regenerate with `python3 tools/make_icons.py`.
- **model.json schema versioning/changelog** (audit "cross-app
  opportunity"): not in scope for this pass; all changes to the bundle
  were strictly additive (`results`, `ledger`, corrected `DC_RHO`).
